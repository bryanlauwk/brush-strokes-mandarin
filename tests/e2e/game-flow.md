# 端到端测试用例（两名玩家）

运行方式：先确保 dev server 在 http://localhost:8080，然后
`python3 tests/e2e/game_flow.py`（需要 playwright）。

| # | 用例 | 步骤 | 预期结果 |
|---|------|------|----------|
| 1 | 建房 + 加入 | A 建房拿房号；B 用房号加入 | 两人都在玩家列表里，房间显示 2 人 |
| 2 | 开始游戏 → 进入选题 | A 按「开始」 | 房间状态 `choosing`，画家看到 3 个题目，其他人看到「正在选题」 |
| 3 | 选题锁定 | 画家点其中一题 | 房间状态 `drawing`，双方在 2 秒内都看到同一个遮蔽题目（字数一致） |
| 4 | 并发选题 | 同时点两个不同题目 | 只有一个题目被锁定，另一个请求报错；两名玩家看到的题目一致 |
| 5 | 超时自动锁题 | 画家 15 秒不选 | 系统自动锁定第一个题目并进入 `drawing` |
| 6 | 快速切页 | 猜题者切到别的标签再切回 | 回来立刻（<1s）拿到最新状态，不停留在旧回合 |
| 7 | 5 秒内重连 | 猜题者刷新页面 | 5 秒内自动用本地身份回房，分数/回合不变，仍是同一题 |
| 8 | 回合轮转 | 一回合结束 | `turn_index` 只 +1，画家换人，每人各画一次 |

## 三人用例（tests/e2e/game_flow_3p.py）

`python3 tests/e2e/game_flow_3p.py [base_url]`

1. 建房后小美与阿强在 5 秒窗口内并发加入，校验「3 人在线」。
2. 开局后三个页面同时抢点第一个题目按钮，只有画家那次生效。
3. 收敛校验：两名猜题者的遮罩与字数完全一致，且画家看到的真实题目字数与遮罩一致。
4. 猜题者 5 秒内重连后，三人视图仍一致。
5. 画家 5 秒内重连后，题目不变（私有题目会重新拉取），三人视图仍一致。

截图输出在 `tests/e2e/screenshots-3p/`。

## 四人 + 弱网测试（game_flow_4p.py）

```bash
python3 tests/e2e/game_flow_4p.py                 # 默认开启网络延迟 + 丢包
python3 tests/e2e/game_flow_4p.py --clean         # 关闭网络损伤做对照
python3 tests/e2e/game_flow_4p.py <base_url>      # 指定环境
```

每位玩家一套网络画像（只损伤数据请求，不影响页面加载）：

| 玩家 | 单向延迟 | 丢包率 |
| --- | --- | --- |
| 阿明（房主） | 0ms | 0% |
| 小美 | 150ms | 10% |
| 阿强 | 350ms | 20% |
| 小狗 | 600ms | 30% |

覆盖用例：
1. 房主建房；其余三人在 5 秒窗口内并发加入（丢包时按真实玩家行为重点「加入」）。
2. 四个页面同时抢点第一个选项，只有画家那份生效。
3. 并发选题后四人题目一致：三名猜题者遮罩与字数完全相同，画家拿到的真实题目字数吻合。
4. 网络最差的猜题者 5 秒内重连，四人视图仍一致。
5. 画家 5 秒内重连，题目不变且四人视图一致。

实测结果（弱网开启）：加入阶段出现 3 次丢包重试，选题后 ~2s 内四人收敛，
两次重连均在 ~0.5s 内恢复且题目完全一致。截图在 `screenshots-4p/`。

配套代码改动：`src/lib/retry.ts` 提供 `retryTransient`，用于加入房间与房间快照轮询，
只对传输层失败重试，业务错误（例如房间已满）仍立即提示。
